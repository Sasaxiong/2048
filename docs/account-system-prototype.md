# 账户系统原型设计

## 1. 文档目标

本文以产品原型说明的方式定义账户系统的核心能力，覆盖：

- 业务账户：面向用户、商户、平台等业务主体的账户开立、查询、冻结、余额管理与业务交易承接。
- 会计核心：面向资金事实的复式记账、会计分录、账务试算、日终对账与审计追踪。

目标是让产品、研发、测试、运营、财务可以基于同一套账户语义完成需求评审、接口设计、原型绘制和测试验收。

## 2. 背景与范围

### 2.1 建设背景

业务增长后，钱包余额、商户结算款、平台手续费、保证金、退款、冻结金额等资金形态会快速增加。如果只用业务订单表维护余额，容易出现：

- 交易成功但余额未更新，或余额更新但订单状态未闭环。
- 可用余额、冻结余额、在途金额口径不一致。
- 财务无法还原每一笔资金变动的借贷关系。
- 对账只能靠人工导出明细核对，问题定位成本高。

因此需要将“业务账户”和“会计核心”分层：业务账户服务业务体验和资金约束，会计核心沉淀不可篡改的会计事实。

### 2.2 本期范围

| 模块 | 本期包含 | 本期不包含 |
| --- | --- | --- |
| 账户主体 | 用户、商户、平台、渠道、内部过渡户 | 复杂集团多层级资金池 |
| 账户类型 | 可用户、冻结户、待清算户、收入户、成本户、应收/应付户 | 资产证券化、复杂授信账户 |
| 交易能力 | 开户、充值入账、支付扣款、退款、冻结/解冻、商户结算、手续费入账 | 跨境清算、多币种汇兑损益 |
| 会计核心 | 会计科目、分录模板、复式记账、试算平衡、日终批次、对账 | 总账系统替代、税务申报 |
| 后台 | 账户查询、流水查询、冻结处理、会计凭证查询、对账差异处理 | 复杂 BI 分析平台 |

## 3. 设计原则

1. **业务与会计分离**：业务账户记录用户视角余额，会计核心记录财务视角借贷事实。
2. **余额由流水推导并可快照**：余额更新必须绑定流水，禁止无流水改余额。
3. **复式记账必平**：每张会计凭证借方金额合计必须等于贷方金额合计。
4. **幂等优先**：所有资金类指令必须以业务请求号保证幂等。
5. **先冻结后扣减**：存在履约风险或异步确认的交易优先走冻结/解冻/确认链路。
6. **可追溯不可物理删除**：账户、流水、凭证只允许状态变更或冲正，不允许物理删除。

## 5. 业务账户设计

### 5.1 核心概念

| 概念 | 说明 | 示例 |
| --- | --- | --- |
| 账户主体 | 持有账户的业务对象 | 用户、商户、平台、支付渠道 |
| 账户 | 主体名下承载某类资金的容器 | 用户余额账户、商户待结算账户 |
| 账户子类型 | 按资金状态或业务用途拆分 | 可用、冻结、待清算、手续费 |
| 业务流水 | 对账户余额产生影响的业务记录 | 支付扣款流水、退款入账流水 |
| 余额快照 | 某一时点账户余额汇总 | 日终余额、实时余额 |

### 5.2 账户主体

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| subject_id | 主体 ID | 全局唯一 |
| subject_type | 主体类型 | USER、MERCHANT、PLATFORM、CHANNEL、INTERNAL |
| subject_name | 主体名称 | 展示与检索使用 |
| cert_status | 实名/资质状态 | 未认证、已认证、冻结 |
| status | 主体状态 | 正常、限制交易、注销 |
| created_at | 创建时间 | 系统生成 |

### 5.3 账户类型

| 账户类型 | 所属主体 | 资金含义 | 是否可交易 |
| --- | --- | --- | --- |
| USER_AVAILABLE | 用户 | 用户可直接消费或提现的余额 | 是 |
| USER_FROZEN | 用户 | 用户因支付、风控、争议被冻结的余额 | 否 |
| MERCHANT_SETTLE_PENDING | 商户 | 已交易成功但未到结算周期的资金 | 否 |
| MERCHANT_AVAILABLE | 商户 | 商户可提现或可抵扣的余额 | 是 |
| PLATFORM_FEE_INCOME | 平台 | 平台手续费收入 | 否，财务处理 |
| CHANNEL_CLEARING | 渠道 | 渠道侧在途或待清算资金 | 否 |
| INTERNAL_SUSPENSE | 内部 | 异常、待确认或差错过渡资金 | 否 |

### 5.4 账户状态

```text
待激活 -> 正常 -> 冻结 -> 正常
             |       |
             v       v
           注销 <- 限制出金
```

| 状态 | 可入金 | 可出金 | 可冻结 | 说明 |
| --- | --- | --- | --- | --- |
| 待激活 | 否 | 否 | 否 | 开户成功但认证或审核未完成 |
| 正常 | 是 | 是 | 是 | 默认可交易状态 |
| 限制出金 | 是 | 否 | 是 | 风控或合规限制 |
| 冻结 | 否 | 否 | 否 | 整体账户冻结 |
| 注销 | 否 | 否 | 否 | 余额清零后关闭 |

### 5.5 账户余额模型

| 字段 | 说明 |
| --- | --- |
| account_id | 账户 ID |
| currency | 币种，默认 CNY |
| available_amount | 可用余额 |
| frozen_amount | 冻结余额 |
| pending_amount | 在途余额 |
| total_amount | 总余额，通常为 available + frozen + pending |
| version | 乐观锁版本 |
| updated_at | 最近更新时间 |

余额更新规则：

1. 金额精度以分为最小单位存储，展示层转换为元。
2. 余额更新必须校验账户状态、交易方向、余额是否足额。
3. 每次余额变更生成业务流水，并关联会计凭证号。
4. 并发更新采用账户维度乐观锁或账户分片锁。
5. 冲正交易不能直接删除原流水，应生成反向流水。

### 5.6 业务账户页面原型

#### 5.6.1 账户列表页

```text
+---------------------------------------------------------------+
| 账户管理                                                       |
+---------------------------------------------------------------+
| 主体类型 [全部 v] 主体ID [________] 账户状态 [全部 v] [查询]   |
| 账户类型 [全部 v] 币种 [CNY v] 金额范围 [____] - [____]        |
+---------------------------------------------------------------+
| 账户ID | 主体 | 账户类型 | 可用 | 冻结 | 在途 | 状态 | 操作   |
| A001   | U01  | 用户可用 | 100  | 20   | 0    | 正常 | 详情   |
| A002   | M01  | 待结算   | 0    | 0    | 980  | 正常 | 详情   |
+---------------------------------------------------------------+
| [导出] [批量冻结]                                  1 / 20 页   |
+---------------------------------------------------------------+
```

关键交互：

- 支持按主体、账户类型、状态、金额区间筛选。
- “详情”进入账户详情页，展示余额快照、流水、冻结记录和操作日志。
- “批量冻结”需要二次确认和审批流。

```text
+---------------------------------------------------------------+

+---------------------------------------------------------------+

+---------------------------------------------------------------+

| ...                                                           |

```

#### 5.6.3 冻结/解冻弹窗

```text
+------------------------------------------+
| 冻结资金                                  |
+------------------------------------------+
| 账户ID：A001                              |
| 可用余额：100.00 CNY                      |
| 冻结金额：[________]                      |
| 冻结原因：[风控/争议/司法/运营调整 v]      |
| 备注：[______________________________]    |
| 附件：[上传]                              |
+------------------------------------------+
| [取消]                           [提交]   |
+------------------------------------------+
```

校验：

- 冻结金额必须大于 0 且小于等于可用余额。
- 运营手工冻结必须进入审批，审批通过后才入账。
- 解冻必须选择原冻结流水，避免无来源解冻。

## 6. 会计核心设计

### 6.1 核心概念

| 概念 | 说明 |
| --- | --- |
| 会计科目 | 财务记账的分类载体，如银行存款、用户负债、手续费收入 |
| 分录模板 | 某类业务交易对应的借贷规则 |
| 会计分录 | 一笔借方或贷方记录 |
| 会计凭证 | 一组会计分录的集合，必须借贷平衡 |
| 会计期间 | 财务归属周期，如自然日、自然月 |
| 试算平衡 | 校验同一期间内借贷合计是否相等 |

| 科目编码 | 科目名称 | 科目类型 | 余额方向 | 示例用途 |

| 100202 | 渠道清算款 | 资产 | 借 | 渠道待清算 |
| 220101 | 用户余额负债 | 负债 | 贷 | 用户可用余额 |
| 220102 | 用户冻结负债 | 负债 | 贷 | 用户冻结余额 |
| 220201 | 商户待结算负债 | 负债 | 贷 | 商户未结算款 |
| 220202 | 商户可提现负债 | 负债 | 贷 | 商户可提现款 |
| 600101 | 平台手续费收入 | 收入 | 贷 | 平台交易佣金 |
| 660101 | 渠道手续费成本 | 成本 | 借 | 支付渠道成本 |
| 224101 | 内部过渡款 | 负债 | 贷 | 异常或差错过渡 |

### 6.3 凭证状态

```text
待记账 -> 已记账 -> 已过账 -> 已关账
   |        |
   v        v
 失败      已冲正
```

| 状态 | 说明 |
| --- | --- |
| 待记账 | 记账请求已接收，尚未完成分录生成 |
| 已记账 | 分录生成且借贷平衡 |
| 已过账 | 已进入日终或总账同步批次 |
| 已关账 | 会计期间关闭，不允许普通冲正 |
| 已冲正 | 已生成反向凭证 |
| 失败 | 分录模板缺失、金额不平或账户异常 |

### 6.4 分录模板

#### 6.4.1 用户充值成功

业务含义：渠道确认收款，用户余额增加。

| 借贷 | 科目 | 金额 |
| --- | --- | --- |
| 借 | 银行存款-备付金 | 充值金额 |
| 贷 | 用户余额负债 | 充值金额 |

#### 6.4.2 用户支付下单冻结

业务含义：支付确认前，用户可用余额转为冻结余额。

| 借贷 | 科目 | 金额 |
| --- | --- | --- |
| 借 | 用户余额负债 | 冻结金额 |
| 贷 | 用户冻结负债 | 冻结金额 |

#### 6.4.3 用户支付成功，商户待结算入账

业务含义：用户冻结余额扣减，商户待结算增加，平台计提手续费。

| 借贷 | 科目 | 金额 |
| --- | --- | --- |
| 借 | 用户冻结负债 | 支付金额 |
| 贷 | 商户待结算负债 | 支付金额 - 手续费 |
| 贷 | 平台手续费收入 | 手续费 |

#### 6.4.4 退款成功

业务含义：商户待结算或平台垫付资金退回用户。

| 场景 | 借贷 | 科目 | 金额 |
| --- | --- | --- | --- |
| 退款主金额 | 借 | 商户待结算负债 | 退款本金 |
| 退款主金额 | 贷 | 用户余额负债 | 退款本金 |
| 退手续费 | 借 | 平台手续费收入 | 退还手续费 |
| 退手续费 | 贷 | 用户余额负债/商户待结算负债 | 退还手续费 |

#### 6.4.5 商户结算出款

业务含义：商户待结算转为可提现，再向银行出款。

| 步骤 | 借贷 | 科目 | 金额 |
| --- | --- | --- | --- |
| 待结算转可提现 | 借 | 商户待结算负债 | 结算金额 |
| 待结算转可提现 | 贷 | 商户可提现负债 | 结算金额 |
| 出款 | 借 | 商户可提现负债 | 出款金额 |
| 出款 | 贷 | 银行存款-备付金 | 出款金额 |

## 7. 核心业务流程

### 7.1 开户流程

```text
业务方提交开户申请
  -> 校验主体资质
  -> 创建账户主体
  -> 按账户模板创建账户
  -> 初始化余额为 0
  -> 返回账户 ID
```

异常处理：

- 主体已存在：返回既有主体信息，不重复创建。
- 账户模板缺失：开户失败并提示配置缺失。
- 部分账户创建失败：整体回滚，避免主体下账户不完整。

### 7.2 用户充值流程

```text
用户发起充值
  -> 支付渠道收款
  -> 渠道回调成功
  -> 账户服务增加用户可用余额
  -> 生成业务流水
  -> 会计核心生成充值凭证
  -> 返回充值成功
```

关键校验：

- 渠道回调必须校验签名。
- 同一渠道订单号只能成功入账一次。
- 账户入账成功但凭证失败时进入待补记队列。

### 7.3 用户支付流程

```text
提交订单
  -> 校验用户可用余额
  -> 冻结用户余额
  -> 商户履约或支付确认
  -> 扣减用户冻结余额
  -> 增加商户待结算余额
  -> 计提平台手续费
  -> 生成会计凭证
```

失败处理：

- 冻结后订单取消：解冻原冻结流水。
- 扣款成功但商户入账失败：进入差错过渡户并告警。
- 手续费模板缺失：交易阻断或进入人工审核，取决于业务配置。

### 7.4 退款流程

```text
业务方发起退款
  -> 校验原支付单和可退金额
  -> 锁定原交易
  -> 扣减商户待结算或平台垫付账户
  -> 增加用户可用余额
  -> 按规则退还手续费
  -> 生成退款凭证
```

关键规则：

- 支持部分退款，多次退款累计金额不能超过原支付金额。
- 已结算交易退款需要走商户可用余额或应收款链路。
- 跨会计期间退款不能修改原凭证，只能生成新退款凭证。

### 7.5 商户结算流程

```text
结算周期到达
  -> 计算可结算订单
  -> 生成结算单
  -> 商户待结算转可提现
  -> 发起银行出款
  -> 出款成功后扣减商户可提现
  -> 生成结算凭证
```

异常处理：

- 银行出款失败：商户可提现余额保持不变，结算单标记失败。
- 银行处理中：金额进入在途状态，成功或失败后关闭在途。
- 对账不平：停止自动结算，进入差异处理。

## 10. 对账与监控

### 10.1 对账维度

| 对账项 | 对账口径 | 差异处理 |
| --- | --- | --- |
| 业务订单 vs 账户流水 | 成功订单金额等于账户流水金额 | 补流水或冲正订单 |
| 账户流水 vs 会计凭证 | 每条资金流水有对应凭证 | 补记凭证 |
| 会计凭证借贷 | 借方合计等于贷方合计 | 阻断过账 |
| 渠道账单 vs 平台账户 | 渠道成功金额等于平台入账金额 | 渠道差错处理 |
| 日终余额 vs 流水汇总 | 期初 + 本期发生 = 期末 | 重算快照并定位异常流水 |

### 10.2 监控指标

- 记账成功率、记账失败率。
- 凭证借贷不平数量。
- 账户余额为负数量。
- 待补记凭证数量和最长等待时间。
- 对账差异金额和笔数。
- 手工资金操作次数和审批超时数量。

## 11. 验收标准

1. 支持用户、商户、平台、渠道、内部户的开户和账户查询。
2. 所有余额变化必须生成业务流水，流水可追溯到业务单号。
3. 充值、支付、退款、结算至少四类交易能生成借贷平衡的会计凭证。
4. 同一 request_id 重复请求时返回同一处理结果，不重复入账。
5. 账户余额不足时支付、冻结、出款必须失败且不产生成功流水。
6. 凭证借贷不平时禁止过账，并可在后台查询失败原因。
7. 日终试算平衡页面可以展示借方合计、贷方合计、差额和明细。
8. 手工冻结、解冻、冲正均记录审批和操作日志。
